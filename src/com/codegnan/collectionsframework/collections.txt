	ConcurrentModificationException:
	================================
	ConcurrentModificationException occurs when a collection is structurally 
	modofied unexpectedly while it is being iteration.
	
	Structural Modification: Adding or removing elements in such a way that is changes
	 the structure of the collection.
	 
	Concurrent does not mean mutliple threads, this exception can occur even 
	with a single thread.
	
	
	Reason for Exception when enhanced for loop is used:
	====================================================
	ArrayList internally uses the iterator, in the enhanced for loop 
	 the iterator traverses/iterators the list.
	- countriesList.remove() in example,modifies the list directly.
	- iterator detects unexpected modification in the structure.
	- so,the concurrent modification exception is thrown
	= the problem occured because the collection is modified directly
	   while iterator is traversing the collection.
	eg:countriesList.remove(country); //here remove is the method of arraylist
	
	When iterator is explicitly used:
	===================================
	iterator.remove() is a method which is specifically designed to safely 
	remove the current element during iterator.
	eg:iterator.remove();
	
	
	FailFast:
	=========
	ArrayList iterator is known as failfast iterator.
	 A Fail fast means when ever an iterator detects unexpected structural modification
	 to the collection during iteration,the iterator quickly throws
	 councurrentModificationException.

Comparable interface :
======================

comparable is an interface , it is used to define the natural or default ordering of objects of a class 

for eg : if we have many employeeobjects , java does not automatically know whether employees should be stored by id or my name or something else

By implementing comparable interface , we can tell java how to sort the employee objects by overriding the method compareTo

comparable interface is available in java.lang package it is generic interface 

theclass whose objects need to be compared implements comparable interface 

we override the compareTo method 

compareTo() method:

syntax:
object1.compareTo(object2)

eg: emp1.compareTo(emp)

- compareTo(0 method returns an integer value)


-> It returns the negative value when the current object must come
before the other object

-> It returns zero if both are equal for sorting

-> It returns a positive value when the current object must come 
after the other object.


Comparator:
============
Comparator is an interface.
It is used to define custom sorting logic for objects
It is present in java.util


With comparable, we can define only one natural ordering 
inside the table.

With comparator, we can define multiple different 
sorting rules outside the class.

It has a method:
int compare(T obj1, T obj2);
It compares two objects at a time.


compare() method returns an int value:
It returns a negative value when the current object 
must come before the other object.


It returns zero if both are equal for sorting

It returns a positive value when the current object must come 
after the other object.


Comparator vs Comparator:
==========================
1.Comparable is in java.lang
  Comparator is in java.util

2.Comparable must be used in the same class.
  Comparator is used in an external different class which is
    used as Custom Comparator
    
3.Comparable interface has a single method
     int compareTo(T o)
  Comparator interface has a method:
     int compare(T o1, T o2)
     
4.Comparable defines natural/default ordering of a class
  Comparator defines custom ordering.
  
We use Comparable1 when there is only way to sort the objects.
We use Comparator when we need different ways to sort 
  the same objects.

Map :
=====

map is used to store data in the form of key value pairs

eg:

key           value

aadhar id   -  citizen
employee id  - employee
roll no     -  student
username    -   user


-  data is stored in key - value pairs

eg :

hashmap map = new hashmap();
map.put("100001","ravi");
map.put("100002","ravikumar");

- keys must be unique
- values can be duplicated
- each key is associated with only one value 
- a value is retrieved using its key
- map is not a child of the collection interface 
- map is a part of collections framework , but map does not extend collection interface 

different implementation classes of map interface :
1 . hashmap
2 . linkedhashmap
3 . treemap
4 . hashtable
